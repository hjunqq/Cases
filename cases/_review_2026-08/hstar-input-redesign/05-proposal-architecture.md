# 提案：自我研究架构

> 提案，非事实。目标是把"挖掘 HSTAR 功能 + 摸清填写方法"从人工变成自动，
> 并尽可能做到**不依赖既有算例**。
>
> **2026-08-28 补充**：本架构原先只有求解器 consumer 侧。hstarpre 表明还必须增加
> producer 侧：控制槽位如何被解释、几何对象如何被选择、哪些 deck 字段被联合生成。
> 综合修订见 `08-revised-architecture.md`。

## 六层

```
L0a 记录布局   每个 reader 的 READ 序列                ← READ 语句       [已验证可提取]
L0b 槽位语义   读进来的变量被谁消费                    ← 变量使用点       [已验证可提取]
L0c 路径选择   哪个 reader 会跑                        ← 调用点守卫/循环  [已验证可提取]
L0p 生产映射   ctl/网格/模板如何联合生成 deck          ← hstarpre producer [新增]
L1  能力空间   每个开关的合法取值 + 各取值解锁的字段     ← 源码分支
L2  合成       文法 + 网格 → 任意能力点的最小 deck       ← 不需要样例
L3  探针       最小网格上批量实验:能不能跑、跑出什么
L4  证伪       消融对 + 不变量:抓"旋钮设了但没起作用"
L5  固化       每条发现落成可执行检查或 schema 约束
```

L0a/L0b/L0c 已由 `tools/extract_dispatch.py` 实证可行（506 条 READ、31 个 reader、
24 个调用点、13 个变量的使用点）。

L0p 不能从 HSTAR reader 反推出来。hstarpre 中已经存在边界拓扑提取、按单元组/材料组筛选、
bbox 与法向联合选面、施工期出现/消失、接触、钢筋与粘结、冷却水管、子模型等生产语义。
这些是新语义 IR 的直接候选映射，但必须逐条与当前 HSTAR consumer 对齐后才能采信。

## L1 已经产出的净新增

同样的方法扫源码里的比较与分支，20 行原型就得到：

| 开关 | 源码中实际存在的取值 | 此前的认知 |
|---|---|---|
| `type_problem` | F Q S E **W WT** | 文档只写 4 个 |
| `type_ABC` | **MIF** VIE | 只知 FIX/VIE，**MIF 完全未知** |
| `bkind` | 1 2 3 4 | 只用过 1、2 |
| `index`(单元类型) | 1 3 5 9 16 18 20 21 22 23 25 26 | 生成器认识一小半 |

（`ikindks` 原型返回空，它走 `select case` 或 derived type 字段，需补一条路径。
这是工程量，不是原理障碍。）

**这些都不可能从样例算例中推出来。**样例只展示被走过的那一条路径。

## L4 是心脏：消融对

本项目全部静默缺陷共享一个形状：语法合法、求解器接受、物理不同。
现有的每一道检查都在坏 deck 上全绿。所以循环必须是**证伪式**的，
而最通用的证伪器是消融对：

> 同一个 deck，只翻一个开关，跑两遍。**结果逐位相同 = 这个开关什么也没干。**

`order_time` 的 `[0,0]` vs `[0,2]`：动力算例换掉质量矩阵指示器，结果必须变。
当年它没被设上，而没有任何东西发现——因为没人跑过那个对照。

消融对抓的是**整类**"旋钮是死的"，不是某一个实例。而且它极便宜
（train01 求解 0.2 秒），并且**对 dispatcher 和语义漂移都是黑盒有效的**——
静态分析越难，它越重要。

## "无算例"能做到什么程度（诚实拆解）

| 要判定的 | 真值来源 | 需要算例吗 |
|---|---|---|
| 格式正确（字段齐、顺序对、条件分支对） | L0 源码 | **不需要** |
| 能跑起来 / 崩在哪 | L3 探针 | **不需要** |
| 旋钮真的起了作用 | L4 消融对 | **不需要** |
| **物理正确** | 解析解 + 不变量 | 需要小验证集，但**不需要工程算例** |

最后一行是硬边界：**没有任何办法从源码推出"这个应力场是对的"。**
物理正确性的一手真值是解析解与不变量——悬臂梁挠度、Lamé 厚壁筒、一维固结、
分片试验、网格加密收敛率、能量平衡、互易性。

**种子已在仓库里**：`cases/cases/lame_cylinder`、`cooks_membrane`、
`benchmark_50x50 / 100x100 / 200x200` 就是经典验证问题。
它们与 `train*` 性质不同——`train*` 是"复现某个人工 deck"，这些是"对照闭式解"。
**这才是可以脱离样例的物理地基**，也是工业 CAE 的标准做法（V&V）。

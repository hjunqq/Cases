# 证据分诊 —— 让"查一个问题"有边界

> 2026-08-29。起因：使用者指出前一阶段"不断发现问题、不断修复"，
> 已经偏离了 `17-case-research-loop.md` 定义的循环，变成没有终点的缺陷考古。

---

## 一、病因

**我们把"理解一个问题"默认成了"再读一段 Fortran"。**

这必然无底：源码是 76k 行、三十年漂移，任何新工具都还会挖出更多。
单步都可辩护（每个缺陷都真、都便宜、好几个是"会出错"级别），
但**跟的是最强的信号，不是循环**，累积起来无界。

一个刺眼的对照：

> `_archive/docs/GEHOMadrid温度场计算说明.pdf` 第一段写着
> **"温度应力场的计算是分两次进行的，第一次…自由度也只有温度一个；
> 第二次把第一次的结果作为荷载加到结构上"**。
>
> 而 `PRJ-4611` 的结论"Q+UT 联立在 YL 主线不可行，下一步走顺序耦合"
> 是靠试错得出的。**祖先程序的说明书一直躺在归档里，没人读。**

`Fem.f90:6` 写着 `M. PASTOR, TONCHUN LI AND P. MIRA, May 1997`——
HSTAR 出自 GEHOMadrid。那两份 PDF 共 21 页，可直接抽取文本。

---

## 二、机制：先分诊，再调查

**在动手查之前，先判断这是哪一类问题。**不同类问题的权威来源不同，
问错来源就是把有界问题变成无界问题。

| 问题类型 | 权威来源 | 成本 | 特征 |
|---|---|---|---|
| **协议类**<br>有哪些字段、几项、什么顺序 | 源码 READ / Deck ABI | 低（已机械化） | 有唯一答案，可枚举 |
| **语义类**<br>这个开关/量是什么意思 | **理论与文档优先**，源码消费点仅用于确认 | 中 | 源码能告诉你数据流向，说不清物理含义 |
| **现状类**<br>我们的算例实际怎么填的 | 语料统计（89 个 deck） | 低 | 二手真值，只说"现状"不说"应然" |
| **正确性类**<br>这个结果对不对 | **守恒律 / 解析解 / 极值原理** | 中 | **绝不用归档对比，绝不用"看着合理"** |
| **判据类**<br>这个量能不能当验收判据 | **理论：它是不是不变量** | 低 | 见 §4 |

### 硬规则

1. **语义类和判据类，先问理论，不问源码。**源码回答"数据流到哪里"，
   回答不了"这个量意味着什么"。今天在 `MIF` 上花的力气，
   一篇讲多次透射边界的文献能直接给出稳定性条件与 `nlaymif` 的含义。
2. **深挖源码语义是最后手段**，动手前要能说明另外三条路为什么不够。
3. **当前问题之外发现的缺陷进待办，不立即修。**这是让流程终止的那条纪律，
   也正是前一阶段缺的那条——每个缺陷都被立即修了，所以感觉无底。

## 二·五、证据还有第二个维度：版本敏感性

**等级高不等于可用。**一份文档可以在物理上权威、在协议上完全过时。

`GEHOMadrid` 那两份说明是 **1997 年版**（`Fem.f90:6` 的署名日期）。
之后这份代码长出了 VIE / MIF / `type_problem=WT` / `Bparameter` 反演外循环 /
PARDISO / 22 个输入文件——本项目记录的每一处格式漂移
（旧格式 `.ftr`、2017 年被注释掉的 `appear_process` 守卫、
`.glb` 的两种头部方言）都是这段时间累积的。

所以每类问题还要再问一次：**这类结论对版本有多敏感？**

| 结论类型 | 版本敏感性 | 老文档能不能用 |
|---|---|---|
| 字段布局、记录 arity、开关取值 | **极高** | **不能**——只有当前源码算数 |
| 数值参数、阈值、默认值 | 中 | 只作线索，须复核 |
| **物理方法**（如温度应力分两次算） | **低** | **能用**——方法比格式活得久 |
| 字段的**原始意图**（这个名字当年指什么） | 低 | 能用，帮助解读命名 |

> `PRJ-4611` 靠试错得出"走顺序耦合"，与 1997 年文档第一段一致——
> 这恰好说明**方法这一层确实没漂**。但同一份文档里的任何字段表，
> 对今天的 deck 都不作数。

**规则：老文档的任何结论，进入 `docs/references/` 时必须
带版本标注，并注明"已用当前源码/探针复核"或"未复核，仅作线索"。**

### 我在这一条上刚犯过错

我发现那两份 PDF 之后，立刻把它称为"最高性价比的未开采资源"、
建议"立刻去读"。那是**看到新来源就过度信任**——
与此前过度信任归档结果、以及 KDT 过度信任样例算例，是同一个动作。

**新来源不等于可信来源。**分诊的第一问是"这是哪类问题"，
第二问必须是"这个来源对这类问题的版本敏感性如何"。

## 三、证据等级

每条结论都要带来源，等级从高到低：

```
守恒律 / 解析解 / 极值原理     ← 判定式，不需要参照物
源码确证（带 文件:行号）        ← 对协议是权威，对物理不是
一手文档（GEHOMadrid 说明书等） ← 对物理是权威
文献                            ← 对物理是权威，需核对版本/假设
语料统计（"88/88 个算例满足"）  ← 只说现状，不说应然，必须显式标注
归档结果对比                    ← 最弱：归档可能来自另一个求解器基线
"看着合理"                      ← 不是证据
```

本会话已有两次实证：`npoinb = npoin` 是**统计依据**（88/88，且该字段读进来
从不使用），已在文档里显式标注；归档对比在 `train02c` 上一致到 1e-8、
在 `train_slope_unknown` 上时间轴差 2 倍——**同一类证据在不同算例上强度完全不同**。

## 四、判据类：先问"它是不是不变量"

这是本会话最贵的一课，单列。

我曾提议把 VIE 的"衰减比"做成验收判据，发现同一算例用位移曲线得 0.842、
用加速度曲线得 4.76 之后，我的反应是**"把分母写死"**。

方向就是错的：**那让这个量可复现，不让它有意义。**
可复现而无物理含义的数，最后一定被拿来调阈值。

正确的第一问是：**这个量是不是不变量？**

```
自重合力对账   Σ反力 = Σρ·V·g          守恒律，是      → 可作判据（实测闭合到 1.4e-9）
极值原理       内部不超边界             椭圆方程性质，是 → 可作判据（抓出 train12）
衰减比         结构衰减 / 输入衰减      随频率/阻抗/波型/几何而变，否 → 不可作判据
放大系数       顶/底峰值比              经验带，半是    → 只报 degraded，不判 fail
```

**不是不变量的量，不要试图"规范化"它——直接不做成判据。**
它可以留作线索（`vie-evaluation.md` 的 1.638 就是这么处理的）。

## 五、积累：解决掉的问题去哪

一个问题被回答之后，结论必须落到下列之一，否则等于没答：

| 结论类型 | 去处 |
|---|---|
| 可判定的不变量 | `harness/mechanics.py` 或 `consistency.py` 的一条检查 |
| 协议事实 | `data/deck-abi.json` 的标注（含**诱饵字段**，见 open #16） |
| 语料现状 | 一条全语料对账测试（如 `test_glb_groups_account_for_header`） |
| 理论/文献 | `docs/references/` 的一条，**带出处与适用条件** |
| **被否决的判据** | **也要记**——否则下一个人会重新提出来（衰减比就是） |

最后一行是本会话新增的：**否定性知识和肯定性知识一样要留存。**

## 六、现有证据语料与缺口

**有：**
- 源码 4 棵树（YL 主线 / HSTAR_Q / Easy_HSTAR / hstarpre 归档），已机械化为 Deck ABI 1724 条
- 89 个算例 deck + 归档结果
- `_archive/docs/` 的两份 GEHOMadrid 说明（21 页，**1997 年版**）
  ← 对**物理方法与原始意图**可用；**对字段布局一律不作数**（见 §2.5）
- `_archive/hstarpre` 的 20 个 `.ctl` 内嵌文档

**缺：**
- **文献语料是空的**（全机 4 个 PDF，两个就是上面那两份）。
  需要时应走检索，并把结论连同出处写进 `docs/references/`。
- 解析解验证集只有零散几个（`lame_cylinder` / `cooks_membrane` / `benchmark_*`），
  未成体系。

## 七、下一步

**不是"去读那 21 页"。**那是 1997 年版，只在物理方法与原始意图这两层可用，
里面的填写规则对今天的 deck 一律不作数——把它当权威，就是在重演
本项目记录的每一次版本漂移事故。

正确的用法是**按需查、且必复核**：当遇到一个**语义类**问题时
（"这个开关是什么意思"、"这个场该怎么耦合"），先去那两份文档和文献里找方法层的答案，
再用当前源码或一次探针确认它还成立，然后连同版本标注写进 `docs/references/`。

**真正的下一步仍然是 `17-case-research-loop.md`：挑一个算例走完六个阶段到放行闸门。**
到目前为止通过闸门的算例数是 **0**——工具建得很好，一次都没用它走完一个算例。

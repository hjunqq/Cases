# 算例研究循环 —— 把 AST 挖掘变成可执行的自我研究

> 2026-08-28。提案 + 已实现的部分。
> 工具：`tools/case_path.py`（新）、`tools/coverage.py`（新）。

## 0. 形式化

AST 给出 1012 条（记录 × 路径条件）。于是：

> **一个算例 = 这棵树上的一条路径。**
> 开关取值选定子树，算例必须且只须填满这条路径上的记录。

这一句把三件此前分散的事统一了：

| 此前分散的说法 | 在这个形式下 |
|---|---|
| "这个算例该填哪些字段" | 解出它的路径 |
| "研究透彻" | 路径上每条记录都有归属，没有一条靠猜 |
| "完成更多算例、理解更深" | 覆盖的格子累加，分母是导出的 |

## 1. 已实现：路径求解器

`tools/case_path.py` 补上了 AST 缺的那块——**守卫求值**。
给定开关取值，解出求解器实际会读的记录序列。

```bash
python3 tools/case_path.py --case train01_gravdam_static
python3 tools/case_path.py --switches type_problem=F,type_ABC=VIE,nblks=2
```

**三值逻辑是刻意的。**守卫里出现未提供的变量时求值为 UNKNOWN，
该分支**保留并标记**，而不是静默丢弃。丢弃就等于重演本项目的核心故障：
求解器要读、而没人知道要填的那条记录。

train01 实测：解出 774 条记录，其中守卫完全确定 138 条，含未定守卫 636 条。

## 2. 循环的六个阶段

### 阶段 0 · 路径求解
输入工程意图 → 选定开关 → **AST 导出**该算例将被读取的记录序列。
产物：`Case Path` = 有序的（文件, 记录, arity, 变量, 为什么走到这里）。
这就是"属于这个算例的独有填写方式"，是**算出来的，不是记住的**。

### 阶段 1 · 槽位归属
路径上每一条记录必须归入四类之一：

| 归属 | 含义 |
|---|---|
| `known` | 映射到一个语义明确的字段 |
| `derived` | 由网格/几何计算得到（并被校验） |
| `default-justified` | 用默认值，**但写明理由与源码出处** |
| `unknown` | **阻断放行** |

这一条就是能挡住 `ikindks` / `nabsfgroup` / `order_time` 三次事故的纪律：
它们当时全都是"没人注意到的 unknown"，被静默填成了默认值。

### 阶段 2 · 预先登记的探针
每个 `unknown`、每个 `default-justified`，配一个预先登记的消融：
`must_change` / `must_preserve` / `must_reduce` + 容差 → 哈希 → 跑 → **机械判定**。
**unknown 只能被探针解决，不能被论证解决。**

### 阶段 3 · 回读
生成 → **独立 decoder** 解码 → 与 Case Path 比对。
比对对象是路径，不是上一步的产物——这是防误差累积的唯一办法。

### 阶段 4 · 物理验收
有解析解的用解析解；没有的用不变量（能量平衡、互易性、网格收敛率）。
**证据等级必须记录**，不能含糊成"通过"。

### 阶段 5 · 结算（放行闸门）

一个算例只有在下列条件全部满足时才可以推出：

```
□ 路径上 unknown 槽位 = 0
□ 每个 default-justified 都有出处或探针
□ 回读与 Case Path 一致
□ 物理证据已记录，且标明等级
□ 新覆盖的 ABI 格子已登记
□ 本次学到的东西已落成会失败的检查，而不是散文
```

**这就是你说的"研究一个算例透彻之后才可以推出"。**
它不是态度要求，是六条可机械判定的条件。

### 第二次运行：修掉一个自己的 bug，前沿收缩到 6 个算例

`local_p4(ipoin)/=1` 卡住 14 个算例——**根因是本项目自己的 harness bug，不是求解器。**

`decoder._INVISIBLE` 是一组 `id()`，只对建立它的那棵树有意义，却按 `is not None`
缓存。单个算例解码时成立；**同一进程里解码第二个算例时静默失效**——树 #2 的每个
节点都命中不了索引，于是每个本该跨过的守卫都变成了停止。更糟的是树 #1 被回收后
id 可能复用，索引还可能把无关节点标成 invisible。现已按 root 对象身份缓存，
并持强引用钉住。

修复后 **18/21 的 deck 能被完整走完**，`local_p4` 与 `nchek` 类停止全部消失。

### 模态不变量（2026-08-29）

模态运行没有力，所以所有基于力的检查在它身上一律 `unverified`——
train03a/03b 就是这么卡住的，**而 `1.chk` 一直在逐阶打印判定所需的一切**：

```
order= 1  omega= 0.25109E+02  freq= 0.39962E+01  period= 0.25024E+00
          mstar= 0.46109E+06  kstar= 0.29069E+09
```

`mstar`/`kstar` 就是 φᵀMφ 和 φᵀKφ。两条判据写进 `harness/mechanics.py`：

| 判据 | 内容 | 为什么是不变量 |
|---|---|---|
| `modal_rayleigh_quotient` | ω² = k\*/m\* | 瑞利商的定义。**不是构造性恒等式**：ω 出自特征值求解器，m\*/k\* 出自组装矩阵的投影，两者对上才说明特征值、特征向量、两个矩阵互相自洽 |
| `modal_spectrum_ordering` | ω > 0 且升序 | K 半正定、M 正定 ⇒ 广义谱实非负；违反意味着刚体方向漏进了特征提取，或排序错了 |

容差由**打印精度**定，不由物理定：`1.chk` 只写 5 位有效数字，所以再精确的解
也无法把商重构到 1e-4 以内。实测残差 6e-7 ~ 4e-5，阈值取 1e-3。

**独立旁证**：train03b（IFS 带水）f₁ = 3.227 Hz < train03a（干）f₁ = 3.996 Hz。
附加质量降低频率——理论预言的方向，两个算例自己给了出来。

单元测试 `modal_first_principles` 覆盖**证伪路径**——真实算例只会走通过分支。

### 前向 goto 的跳过区间（2026-08-29）

`abs(lamda(istep)-lamda_iter)/abs(lamda(istep)).le.1.e-12` 是特征值迭代的收敛
判据（`Fem.f90:10338`），卡住两个模态算例的条件 1。AST 直接给出答案，
不需要读 Fortran 语义：

```
IF 子树 有 READ？               False   （body 只有一个 GOTO）
最内层 LOOP  jiter=1,miter 有 READ？ False
标签 10 continue                        紧跟在该 LOOP 之后
```

原判据是"**宿主**子树不读任何 deck"。对方向未知的跳转这是对的问题，
但对最常见的**提前退出**过强：

```fortran
do jiter=1,miter          ← 不读
   ...
   if (converged) goto 10 ← Fem.f90:10338
end do
10  continue
call load_of_mass(...)    ← 而这里读
```

**标签处及其之后的语句无论跳与不跳都会执行，与布局无关；只有被跳过的那一段
能移动游标。**走到父 SEQ 去要求整段不读，失败纯粹是因为标签**之后**的语句。

新判据：找到 body 里持有目标标签的祖先 SEQ，定位含本节点的那个子节点，
要求**该子节点到标签之间**不读任何 deck。后向跳转一律拒绝——那时跳过区间
不由标签界定。

`decode_all` 的停止原因分布，两次修复合计：

```
本轮之前   11 × 完整走完   10 × 停在守卫
_INVISIBLE 修复后  18 × 完整走完    3 × 停在守卫
前向 goto 修复后   20 × 完整走完    1 × file exhausted
```

**只剩一个停止点**，而且它不是守卫——是 `props(imat)%head` 读到文件末尾，
属于另一类问题（deck 真的短了，或 arity 判错），不是路径不可判定。

### 动力不变量：从输出反推地面运动（2026-08-29）

先量后改。测下来 `tofor` 在这个动力算例里**不含重力**（Σ竖向 ≈ 0，
因为 `force_process=1` 把重力当过程加，动力段只算地震增量响应），
所以"Σ反力 = 自重"这条路在动力上是断的。而全局 d'Alembert 平衡需要阻尼力
`αMu̇ + βKu̇`，其中 `βKu̇` 拿不到 K 就算不出——**不是缺理论，是缺输出。**

真正可用的是一条**纯运动学恒等式**：

$$\ddot u_{abs}(\text{node},t) = \ddot u_{rel}(\text{node},t) + \ddot u_g(t)$$

绝对加速度 = 相对加速度 + 整个域的刚体平动，所以
**`ü_abs − ü_rel` 必须在每个节点上是同一个向量**。不涉及质量、刚度、阻尼，
任何同时输出这两个块的算例都能查，而且**顺带把求解器实际施加的地面运动反推出来**。

这正是关键：本项目最贵的动力事故 PRJ-6057 就是**地震从未进入右端项**——
deck 声明了曲线，求解收敛，位移画出来像那么回事，而地面根本没动过。
当时所有检查都通过。这一条不可能通过：deck 声明了某方向有曲线而反推的
ü_g 在该方向恒为零，是**自相矛盾**，不是容差问题。

**副产品：一个决定性实验。**同一个 deck 只改 `earthquake_curve` 槽位：

| deck | 反推 ü_g,x | 反推 ü_g,y |
|---|---|---|
| `(2, 0)` | **0.275035** | 0.000000 |
| `(0, 2)` | 0.000000 | **0.275035** |

**"槽位是方向、取值是曲线"由实验确证**，不再是文档里的一句话。
（顺带发现：`cases/train02_gravdam_seismic` 的 deck 是 `(0,2)`，即**竖向**激励，
而生成器写 `(2,0)` 水平。见 §6 待决事项——**未改动该算例**。）

两个容差陷阱，都在单元测试里钉死了：

1. **过零点**：ü_g 每周期过零，按瞬时值归一化等于拿噪声除以 ~0
   （第一版在好算例上报了 0.33）。
2. **灾难性抵消**：train02 打印 `-185.53732` 和 `-185.70464`，八位有效数字，
   差值 0.167 只剩五位。**按被减数的量级归一化，不按差值的量级**——
   同一个 1.4e-5 的抖动，除以 0.275 是 5e-5（误判 fail），除以 185 是 8e-8
   （它真实的样子）。

VIE/MIF 算例一律 `skip` 而非"通过"——它们经 `earthquake_curve_d/_v` 驱动，
这条检查读不到。**空洞的通过就是把 `unverified` 当 `pass`**，正是要避免的。

### 条件 3 变成机械的：语义回读

`roundtrip_matrix.py` 按行比对重新生成的 deck，**会过报**。本项目已有实证：

```
0  0  0  0  0  0  0  0        (原始，train02)
0  2                          (生成)
```

`Global.f90:1131` 在这里只读**一项**，Fortran 的记录尾丢弃规则把其余全部
丢掉,两份 deck 都绑定 `order_time = 0`。文本 diff 判它不同，求解器分不出来。

条件 3 真正问的是**求解器看到的是不是同一份 deck**，而 Deck ABI 解码器
可以直接回答：走完两份 deck，比对 READ 绑定的 `(位置, 变量, 取值)`。

`tools/semantic_roundtrip.py` 做的就是这件事，并且分三类计数：

| 类别 | 含义 | 是否算差异 |
|---|---|---|
| **数据不同** | READ 绑定的数值不同 | **是**——求解器会读到不同的值 |
| 注释不同 | `text` 读入的抬头行不同 | 否——读进一个丢弃变量 |
| 数值等价 | `0` vs `0.0`、`50` vs `50.0` | 否——同一个 REAL |

后两类必须分开：第一版按字符串比，`0` vs `0.0` 让**每一个算例**都报差异，
`.mat` 里 34 处 `COMMENT` 抬头成了全语料最大的"差异"，
真正改变物理的那些被埋在噪声底下。

**train01 语义上完全一致**（242 条记录 0 处不同），而文本矩阵说它 `1.man 2L`。
条件 3 从"manual（等于免检）"变成可判定，**闸门因此变严**：
train02 从 READY 退回 BLOCKED,因为它的 import 确实丢了地震。

三次修复里有**两次的根因是本项目自己的工具**（`_INVISIBLE` 缓存、
过强的 goto 判据），一次是输出开关。**没有一次需要深挖求解器的物理语义。**
这正是 `28-evidence-triage` §2 硬规则 2 的验证：深挖源码语义是最后手段。

## 3. 累积性：覆盖账本

`tools/coverage.py` 把"理解程度"变成一个有导出分母的数：

```

21 个算例确定覆盖 224 个 (32.7%)

  .glb  100/127  78.7%      .ifs   19/21   90.5%      .opr  12/18   66.7%
  .nrt    9/43   20.9%      .loa   25/260   9.6%      .mat  11/116   9.5%
```

> 2026-08-29 更新。上一版是 138/424 (32.5%)。**绝对覆盖涨了 62%**，

这还带来一个此前没有的能力：**在动手之前就能估算一个新算例的研究成本**——
把它的开关喂给路径求解器，数一数落在未覆盖格子上的记录有多少。
**零新增格子的算例是廉价的复用；新增格子多的算例才是真正的研究。**

## 4. 覆盖率的当前数字是下界，而原因指向同一个瓶颈

> 本节写于 `.loa` / `.pre` 还是 0% 的时候，前向 goto 判据落地后已不再成立
> （见 §3 的更新）。**结论仍然成立**：边际贡献除少数算例外仍全是 0，
> 瓶颈没有变，只是起点抬高了。

上表原文里 `.loa` / `.pre` 覆盖 0%，而且**21 个算例覆盖的是同一批格子**
（边际贡献除第一个外全是 0）。

**这不是关于算例的发现，是仪器的限制。**
`switches_from_deck` 只从 `.glb` 头部三条记录取开关，所以环境很薄；
`.loa` / `.pre` 的守卫依赖的是**在这些文件内部先读到的值**（`ntcurve`、
`nfixsets`、`ngroup`…），求值不出来，于是全部记为 UNKNOWN，不计入"确定覆盖"。

要拿到真实覆盖率，需要**边读边绑定**：从 deck 读出一个值 → 绑进环境 →
它决定后面的守卫与 arity。而这恰好就是**共享 decoder**。

> **覆盖率度量和共享 decoder 是同一件事。没有 decoder，就没有真实覆盖率。**

这让 `10-roadmap.md` 的 **P0-1（独立 decoder）成为真正的枢纽**——
往返比对、ABI 驱动的校验、覆盖账本，三件事共用它。
而且路径求解器已经把它做了一半：路径 + arity 就是解码器的骨架，
差的只是把读到的值反馈回环境。

## 6. 诚实的边界

1. **覆盖率 32.5% 是下界**（见 §4），真实值需要 decoder 才能测。
2. **分母只覆盖 6 个主 deck 文件**；还有 9 个输入文件、约 257 条 READ 未建模
   （open #12）。所以 424 这个分母本身也会涨。
3. **物理正确性不能自我认证**，超出解析解集合就不行。阶段 4 的证据等级
   必须如实记录，不得把"跑通且不变量成立"写成"结果正确"。
4. **路径求解器不做可达性分析**：它不判断一组开关取值在物理上是否自洽，
   只回答"若如此取值，会读到什么"。

## 7. 为什么这个循环值得信任

不是因为 agent 聪明——本会话的五个探针里，agent 的推理错了 **8 次**，
其中 6 次是同一条文本归一化规则。全部由协议兜住。

这个循环成立，靠的是同样的四个条件：

```
问题有限可枚举     ← ABI 的 424（将增长）个格子，不是开放探索
真值来自外部       ← 源码 / 解析解 / 既有 deck，不是上一步的产物
判定机械           ← 阶段 2 与阶段 5 的闸门由脚本执行
验证回路秒级       ← 路径求解 <1s，最小算例求解 0.2s
```

**四条缺任何一条就退化。**而它们都可以工程化——这正是这个循环能落地的理由。

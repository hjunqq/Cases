### 七个"会出错"的缺口（本轮堵上）

| 缺陷 | 形态 |
|---|---|
| `deck_text` 引号切词 | 整条记录错位一格，绑一整排错值 |
| `!` 整行注释被当空记录 | 跳过它、吃掉下一行的真实数据 |
| `case default` 从未被选中 | SELECT 什么都不读，游标滞后 |
| 剪枝把 `if` 的守卫剪没了 | 无条件走 else，读求解器不读的记录 |
| 单行 `if` 括号守卫截断 | 藏掉 315 个控制流节点，树本身不完整 |
| 整数组读当 1 项 | 1001 项读 1 项，游标滑掉 1000 项 |
| `criteria(1:2)=='MC'` 子串比较 | 答错而非未定 |

> **五处在被发现前已经在产出错值，只是撞上 EOF 或非数值 token 才停住。
> 它们不是被协议兜住的，是被运气兜住的。**

区分很重要：前六处文本层 bug 造成"**读不到**"（会自己暴露），
引号那处造成"**读到了而且是错的**"（不会）。后者才是危险类别。

### 生产代码里修掉的三个静默缺陷

- `mesh_io` 静默丢整行 —— `pile_beam` 返回**零个组**，无异常无告警，
  下游全部照单全收（`24-*.md §1.2` 称之为"本项目主症状最纯粹的标本"）
- `generator.kpload` 被写成点荷载组数 —— ≥2 组时静默切到错误的荷载格式
- `.glb` 头两种方言按位置硬编码 —— `train_temp_creep` 解出 `ndimn=1`

### 两个会让人得出错误结论的环境陷阱

- **8 个求解器源文件是 GBK**，普通 `grep` 静默跳过
- **31/89 个 `.glb` 对普通 `grep` 完全不可见**（静默零输出 + rc=1），
  而解析器丢掉的那两个算例**正在这 31 个里**——**工具看得见、人看不见**

### 下一步：需要的是新算例，不是新代码

decoder 剩余的停止点**全部**是算例缺陷或真运行时量：

## 一、我们现在知道什么（已验证，不再讨论）

### 1. 问题的形状

**本系统的主症状是：语法合法、求解器接受、物理不对。**
"能跑通"不是证据，"检查全绿"也不是——查实的两个 VIE 算例都是全绿且边界残缺的。

### 2. 能力住在哪里

基准套件 15 个算例，**8 个是 `legacy_deck`**（人工 deck 被重放）。
套件全绿测的是"求解器还能不能复现这些 deck"，不是"工具链能不能造出它们"。
21 个 train 算例只有 7 个有 `config.json`。

### 3. 生成器是精确的，缺的是导入器

从人工 `config.json` 生成：**train01 六个文件逐字节等价**，其余 1~5 行差异全部是
有意改动。Mode C 的两半（`import_glb` / `generate_all`）从未对接。

已修：`.pre` 忠实往返 2/21 → **21/21**，`.LOA` 4/21 → **15/21**。

### 4. deck 不是"一份格式"

**506 条 READ、31 个 reader**。一个文件被多个子程序依次消费同一条流：

```
.man → 17 reader    .glb → 6    .ifs → 4    .pre → 3    .loa → 2    .mat → 1
```

真实结构是 `(dispatch 路径, 开关状态) → 记录布局 × 槽位语义`。
**槽位语义不在 READ 语句里**，只在变量的消费点。

### 5. 知识分散在三处，没有一处完整

```
HSTAR reader        ← 消费协议、运行时分支（最终裁判）
hstarpre (24k 行)   ← 历史生产语义、几何/拓扑算法
Python generator    ← 当前 Web 生产与迁移
```

### 6. 已确认的具体缺陷

| 缺陷 | 状态 |
|---|---|
| `.pre` 约束集 / `.LOA` 边荷载无法往返 | ✅ 已修 |
| `elem_info` 静默把未知单元变 Q4（含 B20→Q4） | ✅ 已修（+Q8 表项） |
| `.glb` 头两种方言，`parse_glb` 按位置硬编码 | ✅ 已修（open #7，按标签名对齐） |
| VIE 下 `earthquake_curve` 双重激励 | ✅ 已实证（open #2）；但需 `force_process/=0`，见 open #15 |
| `train10` 30 条吸收边错位 / 61 段未覆盖 | ❌ 未修（open #5） |
| 5 个旧格式 deck | ✅ 已确认（`.glb` 差 4 条记录 14 字段，可机械迁移） |
| `type_problem` 的 `W`/`WT`、`type_ABC` 的 `MIF` | ✅ 已完整解剖（open #3/#4） |
| 四种未支持的时间曲线 | ✅ 已解剖（open #11）：HARMONIC 最易接，ARCLENGTH 是求解器缺代码 |

## 二、方向（一句话）

> 不重写求解器，不迁移任何 deck。建一个**输入编译器**：
> 以强类型 CAE Semantic IR 为工程真值，
> 以当前 HSTAR reader 为协议裁判，
> 吸收 hstarpre 的生产语义，
> 一切产物必须**独立回读比对**。

`Easy_HSTAR` 的初衷（现代化输入）保留；它当初的问题是把
"新输入格式"和"重写 30k 行求解器"绑在了一起。**解绑，只做前者。**

## 三、执行计划

### P0 · 建立事实与最小护栏（当下）

**目标：不写新架构也能立刻降低风险，并解锁 schema 设计。**

| # | 任务 | 成本 | 为什么现在 |
|---|---|---|---|
| P0-1 | **独立 decoder + 回读比对**独立成件 —— **枢纽**（decoder 已交付、文本层已合并；语法层待 decoder 覆盖到 .pre/.man 后再换） | 小（`case_path.py` 的路径+arity 已是骨架，差把读到的值反馈回环境） | 不需要 IR。往返比对、ABI 驱动校验、覆盖账本三件事共用它；没有它就没有真实覆盖率（见 `17-case-research-loop.md` §4） |
| P0-2 | `.man` 12 个静力 reader 布局比对（open #8） | 很小，纯源码 | **schema 设计的前置条件**：决定静力分支要不要再分和类型 |
| P0-3 | 5 个可疑 `.LOA` 过当前求解器（open #1） | 小 | 决定 Deck ABI 要不要留旧格式分支 |
| P0-4 | VIE 双重激励消融对（open #2） | 小 | 第一个带**预期关系**的 probe 标本（`must_change`） |

**P0 的验收**：每个算例的往返结论都能说清"证据来源是什么"，而不只是有个数字。

### P1 · 中间模型（三条纵切）

`Deck ABI v1` → `Semantic IR v1` → `Deck Plan + source map` → `strict generator adapter`。

首批**只做三条纵切**，每条必须完整通过：编译门控 → 回读比对 → 数值探针 → **至少一个物理 benchmark**。

```
纵切 1  线弹性静力        （benchmark: lame_cylinder / cooks_membrane，仓库已有）
纵切 2  固定边界动力      （benchmark: 待定，建议单自由度解析解）
纵切 3  VIE 动力          （benchmark: 能量账——零材料阻尼下离开模型的能量
                            只能是辐射出去的。**不要用衰减比**：它随频率成分、
                            阻抗比、波型、覆盖几何而变，同一算例用位移曲线得 0.842、
                            用加速度曲线得 4.76，是两个不同的量，见 vie-evaluation.md）
```

**capability profile 必须带 `evidence:` 字段**——记录证据来源，不只是 pass/fail。
（hstarpre 的 20 个样例只覆盖 Q/S + PARDISO，对 F/E/W/EXPLICIT/VIE/MIF 这条证据是空的。）

### P2 · 迁移 hstarpre 的差异能力

按价值/耦合风险排序，**行为迁移而非代码嵌入**——先建输入输出夹具与映射表，
再把算法重写为纯函数、可单测组件：

```
1 通用拓扑/几何选择器    2 施工阶段与激活    3 RC steel/bond
4 FSI/吸收边界           5 接触与薄层        6 冷却水管
7 子模型与反演辅助文件
```

每迁移一项，新增：capability profile + producer golden + roundtrip test + physics probe。

### P3 · 自我研究闭环

`05-proposal-architecture.md` 的 L1/L3/L4：能力空间枚举 → 最小网格探针 → 消融对。
**消融对必须声明预期关系**（`must_change` / `must_preserve` / `must_reduce`），
不能只看"结果是否不同"。

## 四、几条不可协商的原则

1. **单向真值**：格式 → deck。deck 是构建产物，像 `.o` 一样不手改、可重建。绝不双向同步。
2. **表达不了就拒绝**，不填默认值。静默降级是本项目的主症状，也是最难发现的 bug 形态。
3. **和类型**：让错误**写不出来**，而不是靠检查抓。VIE 分支下 `acceleration` 字段不存在。
4. **知识必须落成会失败的检查**，不能落成散文。`capability-inventory` 第四轴用散文写下
   "`ikindks` 只能手改"，一天后照样撞上去。
5. **每条结论追到源码行号或一次实验。**

## 六、算例研究循环（2026-08-28 新增，见 `17-case-research-loop.md`）

**算例 = Deck ABI 树上的一条路径。**六阶段：路径求解 → 槽位归属 → 预先登记探针
→ 回读 → 物理验收 → 结算。放行闸门是六条可机械判定的条件，
其中第一条是「路径上 unknown 槽位 = 0」。
覆盖账本让"完成更多算例、理解更深"成为有导出分母的数，
并能在动手前估算一个新算例的研究成本。

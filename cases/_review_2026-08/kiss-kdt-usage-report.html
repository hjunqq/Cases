KISS：值得取的三样

都不需要引入它的目录结构就能吸收。

1 · boundary.scope_out —— 明写"不能算什么"

信噪比最高的一段。填这个字段时被逼出来的最有价值的一条是：这套 conforming 网格共节点、界面上没有压力自由度，根本算不了扬压力。重力坝抗滑稳定验算离不开扬压力——而 docs/references/ 十三篇里没有任何一处写过这件事。references 全是"怎么做 X"，从来没有一处系统地写"X 做不了什么"。

2 · severity: silent + remedy.prevention

severity 把失败分成 silent / degraded / fatal 三级；prevention 要求每条知识指向一个会自动跑的检查，否则就得承认"没有防护"。两者配合，逼你面对"现有检查其实挡不住最危险的那一类"。

3 · 可执行的 preflight + 结构化 result.json

KISS 自带那份 preflight_check.py 是自动生成的样板（还硬编码了作者服务器路径），但规格要求它发出 PREFLIGHT_REPORT= 结构化行，每项带 {kind, subject, critical, status, fix}，且失败项必须带 fix。这个契约对 HSTAR 完全适用。

最硬的一条实验证据

建包时被 inputs[].notes 那个"这个输入缺失会怎样"的字段结构问出一个此前无人记录的缺陷，随后做了对照实验：只删 gravdam_meta.json，其余全同。

结果：水压整个消失，坝顶位移 0.26 mm vs 15.6 mm（60 倍），而 physics_gate、坝顶位移符号、量级、两步施工、组序、全局平衡——六项通用检查全部通过。无水时坝顶仍有 +0.26 mm 的泊松外鼓，符号是对的。只有专门检查"实际施加了几条水压边"的那一条抓住了它。

推论：通用门控挡不住"荷载整个丢了"这类失效，真正有鉴别力的是逐算例族的输入溯源检查。

格式装不下的东西

工具链的编程接口契约。KI 包围绕求解器设计：inputs[] 描述求解器吃什么文件、什么单位，triplets 描述填错会怎样。整套 schema 里没有一个位置能放下"mesh_io.read_elements() 返回 [(eid,[n…]),…] 而不是 dict"。对 ADCIRC 那种 4 个 convert_* 工具够用；对 skills/ 下 20+ 个互相 import 的脚本，"知道求解器要什么"和"知道怎么调用这个仓库"是两个规模相当的知识体，它只覆盖前者。

不值得取的

  • knowledge_infrastructure.yaml 与 workflow/workflow.md——ADCIRC 那两份是自动生成的空壳：description 全空、tools 全空、stage 全 TBD、依赖全 none
  • 跨模型编目字段（ki_class/spatial/temporal/closure）——为在一个平台上比较 ADCIRC/VIC/CaMa-Flood 而设，我们只有一个求解器
  • processes.modules——HSTAR 是单体 Fortran 二进制，没有可插拔物理模块
  • forcing / initial_conditions——水文气象模型的形状

KDT：跑不起来的部分与能用的部分

组件本机
verify_ki_structure.py（裁判）已实测只需 Python 3.12 + PyYAML
build_dissection_prompt()（规格）已实测纯字符串拼接；打印出了给 HSTAR 生成的完整 prompt，那是"一个 KI 该长什么样"最权威的描述
kdt-release/MIT纯文档 + 模板 + 3 个 validator，唯一可安全取物的地方

一个值得记的架构事实：它的 LLM 后端就是 claude CLI 本身——subprocess.run(['claude','-p',prompt,'--allowedTools',…])，没有 API key、没有 SDK、没有状态图。独立评审员是另起一个 codex CLI 子进程。

反向发现：它的裁判自己有一条不可失败路径

我们的 dag.yaml 压根没有 outputs: 键，而裁判对 dag 报了零条失败：

_outs = (_dag.get("outputs") or [])
_obs  = [o for o in _outs if (o.get("observability") or {}).get("comparable_obs_shapes")]
if _outs and not _obs:      # 空集合直接短路

一个完全没有输出定义的 dag 干净通过——恰是它自己文件头那句 "a stage that cannot fail is not a check" 的反例。教训可直接用：if X and not Y 天然放过 X 为空的情况。

最有价值的：七条元规则

比它的组件清单值钱得多，每条都有事故背书。

  1. 不能失败的阶段不是检查——数数不设阈值 = 假检查
  2. 检查跑不起来 = 失败，不是通过
  3. "两种都接受"的读法是不可失败的检查——旧版同时接受新旧键名，把 240 个未迁移的块藏了好几周
  4. 先做回填运动，再把 warn 翻成 fail，绝不制造几百个瞬间失败
  5. 区分"真缺"与"叫法不同"——报错错了会派人去重写已经存在的东西
  6. 查询失败要回落到最严格的一档
  7. 检查器与生成器必须共用同一套读取函数

三步验证法

Step 1 用模型自带样例原样跑通（只证明二进制和环境）→ Step 2 渐进式数据替换，一次只换一个组件并回归比对，硬规则是"第 i 步没跑出合理结果不许进第 i+1 步" → Step 3 全本方数据跑标准算例。状态标签 binary_only → partial_replacement → full_replacement → production_validated。

反模式清单里最锋利的一条：

关于"结果不一样但模型能跑"

不一样多少？10% 是率定，10× 是单位错，1000× 是列映射 bug。

一处必须更正的数据

"带 KI 84% vs 不带 40%"

KISS README 的原文是 3000 试验 / 10 个 agent / 5 个平台 / 14 个里程碑 / NSE ≥ 0.2，带 KI up to 84%，去掉 KI 无 agent 超过 40%。三点此前引用时没说清：

  • 是 "up to"，不是中位数
  • 判定代码与试验记录在两个仓库里都不存在——是作者声明，不是可独立复现的证据
  • KDT 里真正做过、有数字、样本先锁定的对照实验是另一个

Caravan 配对臂才是该照抄的方法论模板：锁定 30 个流域后跑三条臂——默认参数 test-NSE 中位数 −0.05 / 人工 DDS +0.56 / agent 自主设计 0.555 vs 同流域人工 0.475。有地板臂、配对比较、报分布不报均值。

这次评估不是以"引入 KISS 目录结构"收尾的，而是以下面这些收尾。

两者各自的盲点也都被实测暴露了，并写进了我们对应实现的注释：KISS 的续跑只看产物存在性、不检测输入变化；KDT 的裁判有不可失败路径。

取舍

吸收

  • scope_out：明写不能算什么
  • severity: silent 与 prevention
  • PREFLIGHT_REPORT= 结构化契约
  • 七条元规则
  • 三步验证法与 10%/10×/1000× 判据
  • Caravan 配对臂的实验设计

不动

  • KI 包目录结构
  • 自动生成的空壳文件
  • 跨模型编目字段
  • 文献管线（我们的判据来自解析解与基准算例）
  • 38 词地学介质词表

自研为主干。把"重打包成 KI 包格式"降级为一个只读导出器，且不早于内部清单建成——他们格式的价值来自 119 包 × 14 域的横向复用，我们只有一个求解器，跨模型迁移收益接近零。可发表性的路径不是换格式，是补 Caravan 那种配对臂数据。
